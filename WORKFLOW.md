# CTW Analysis Workflow

Complete end-to-end analysis pipeline for Capture the Wool maps and matches.

## Overview

The workflow orchestrates three analysis stages:

1. **Layout Analysis** - Extract block data from Minecraft world folders
2. **XML Analysis** - Parse map configuration from XML files
3. **Match Analysis** - Analyze match data using layout and configuration

## Quick Start

```bash
# Analyze a single map (all steps)
python run_analysis_workflow.py --map tumbleweed

# Analyze all maps
python run_analysis_workflow.py --all

# Force regeneration of all files
python run_analysis_workflow.py --map tumbleweed --force
```

```
└── <match-id>.parquet       # Match event logs
```

## Step 1: Layout Analysis

Extracts block data from Minecraft world folders in Anvil format (Java Edition 1.8.9).

**Input:**
- `map_folders/<map>/region/` - Minecraft region files

**Output:**
- `map_folders/<map>/layout_y0.parquet` - All blocks at Y=0
- `map_folders/<map>/layout_top_surface.parquet` - Top surface blocks
- `map_folders/<map>/layout_vertical_density.parquet` - Vertical density map
- `map_folders/<map>/layout_bedrock.parquet` - Lowest bedrock blocks

**Skip if:**
- All parquet files already exist
- Use `--force` to regenerate

## Step 2: XML Analysis

Parses map configuration XML and extracts structured data.

**Input:**
- `map_folders/<map>/map.xml` - Map configuration file

**Output:**
- `map_folders/<map>/map_data.json` - Structured map data including:
  - Teams and spawns
  - Wool objectives
  - Region definitions
  - Build restrictions

**Skip if:**
- JSON file already exists
- Use `--force` to regenerate

## Step 3: Match Analysis

Analyzes match data using layout and XML information. Generates plots and reports for each match.

**Input:**
- `map_folders/<map>/layout_bedrock.parquet` - Bedrock layout from Step 1
- `map_folders/<map>/map_data.json` - Map data from Step 2
- `match_logs/match_history.txt` - Match to map mapping
- `match_logs/<match-id>.parquet` - Match event data

**Output:**
- `map_folders/<map>/matches/<timestamp-match-id>/` - Match analysis folder containing:
  - `all_teams.png` - All players visualization
  - `red_team.png` - Red team visualization
  - `blue_team.png` - Blue team visualization
  - `match_summary.pdf` - PDF report with statistics
  - `match_summary.txt` - Text summary
  - `classification_report.pdf` - PDF report with role classifications
  - `classification_report.txt` - Detailed text report with role analysis
  - `path_network_combined.png` - Combined path network visualization (6 methods)
  - `path_network_red_team.png` - Red team path network
  - `path_network_blue_team.png` - Blue team path network

**Skip if:**
- Match analysis folder already exists
- Use `--force` to regenerate (not yet implemented for matches)

## Command-Line Options

### Map Selection

- `--map <name>` - Analyze a specific map (e.g., `tumbleweed`, `kanto`)
- `--all` - Analyze all maps in `map_folders/` directory

### Control Options

- `--force` - Regenerate all files even if they exist
- `--no-layout` - Skip layout analysis (Step 1)
- `--no-xml` - Skip XML analysis (Step 2)
- `--no-matches` - Skip match analysis (Step 3)

### Match Configuration

- `--match-history <path>` - Path to match history file (default: `match_logs/match_history.txt`)

## Examples

### Full Analysis

```bash
# Complete analysis for one map
python run_analysis_workflow.py --map tumbleweed

# Analyze all maps
python run_analysis_workflow.py --all
```

### Incremental Updates

```bash
# Only update XML data (layout already exists)
python run_analysis_workflow.py --map kanto --no-layout --force

# Only run match analysis (layout and XML exist)
python run_analysis_workflow.py --map tumbleweed --no-layout --no-xml
```

### Debugging

```bash
# Regenerate layout data only
python run_analysis_workflow.py --map tumbleweed --force --no-xml --no-matches

# Skip match analysis (not yet implemented)
python run_analysis_workflow.py --all --no-matches
```

## Integration

The workflow coordinates three analysis modules:

- **layout_analysis/** - Block extraction from world files
- **xml_analysis/** - XML configuration parsing
- **match_analysis/** - Match event analysis (pending implementation)

Each module can also be run independently for more control.
